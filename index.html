思科Nexus：为RDMA配置验证无损以太网

AI智算网络配置实战高级思科

Nexus实测验证RDMA无损以太网

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

RDMA业务对丢包高度敏感，交换机与服务器无损配置不一致或未验证时易出现性能下降与重传。

核心技术

在Nexus与服务器两侧对齐无损队列、PFC优先级与拥塞标记配置，并用交换机和服务器的真实统计验证丢包、暂停与队列状态。

怎么做配置

configure terminal
配置无损队列的class-map/policy-map与PFC优先级
接口启用PFC与ECN相关QoS策略
服务器侧启用RDMA网卡的PFC/ECN并对齐优先级
show interface priority-flow-control 查看PFC统计
show队列与ECN标记计数验证无损

运维 / 排障要点

用show interface priority-flow-control等看PFC统计并对比服务器侧计数；常见坑是两侧优先级映射不一致导致无损队列未命中。

原文：www.networktcpip.com

华为RoCE连接：以太网交换机无损配置

AI智算网络配置实战进阶华为

双交换机承载RoCE复制链路保无损

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

存储复制走RoCE时网络丢包容忍度极低，普通以太网转发无法保证复制链路的无损与可靠性。

核心技术

复制链路双归属接入两台交换机做冗余，交换机需支持无损传输，通过PFC、ECN等无损机制满足RoCE复制的高可靠低丢包要求。

怎么做配置

将复制链路分别接入两台以太网交换机
为RoCE优先级队列启用PFC无损流控
配置ECN与无损队列保证低丢包转发
核对交换机支持无损能力与链路双归属
用display命令查看接口状态与丢包计数

运维 / 排障要点

用display看接口丢弃、PFC暂停与队列计数，复制链路单交换机故障演练必做；常见坑是双链路实际落在同一台设备失去冗余。

原文：info.support.huawei.com

RoCE AI Fabric：自适应路由与多轨架构

AI智算网络架构设计高级其他

自适应路由加多轨架构突破ECMP瓶颈

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

大模型训练中传统ECMP按流哈希易冲突、链路流量不均，导致链路利用率低且线性加速比难以提升。

核心技术

自适应路由AR按链路拥塞逐包动态选路替代ECMP按流哈希，结合Rail-Optimized多轨架构对齐GPU通信，提升利用率与加速比。

怎么做配置

规划Rail-Optimized多轨拓扑与GPU网卡对齐
Underlay启用自适应路由AR逐包选路
配置DCQCN/ECN/PFC实现无损与拥塞控制
多平面隔离并验证链路负载均衡
用集合通信压测验证加速比与链路利用率

运维 / 排障要点

重点看各成员链路利用率是否均衡与集合通信时延；逐包选路场景还需关注乱序对上层通信库的影响。

原文：ai-hpc.org

AI集群RoCEv2：ECN与PFC阈值平衡

AI智算网络运维经验高级其他

ECN与PFC阈值平衡决定AI集群拥塞

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

大规模AI训练集群拥塞时GPU利用率下降、作业完成时间拉长，RoCEv2拥塞控制调不好会加剧问题。

核心技术

ECN在拥塞早期标记并让端侧降速，PFC按优先级暂停发送保无损；合理拉开两者阈值，让ECN先调节、PFC只兜底，避免暂停扩散。

怎么做配置

在RoCE队列上启用ECN标记并配置门限区间
为无损优先级启用PFC并配置触发门限
保证ECN先于PFC触发、PFC仅作最后防线
在网卡与交换机两侧保持队列与优先级一致
压测中逐步调整门限并观察GPU利用率

运维 / 排障要点

监控ECN标记计数与PFC暂停帧：暂停帧频繁说明阈值过低或拥塞已严重，几乎无ECN标记则可能门限过高未提前调节。

原文：techcommunity.microsoft.com

数据中心网络：Spine-Leaf、VXLAN/EVPN与多厂商命令

数通路由交换架构设计进阶思科、锐捷、华为、新华三

四厂商命令对照看懂数据中心网络

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

数据中心承载高并发业务时，要求高可用、低延迟、多租户隔离，传统架构与单厂商命令经验难以满足。

核心技术

以Spine-Leaf无阻塞为骨架，叠加VXLAN Overlay做虚拟化、EVPN做控制面，再结合链路聚合与微分段实现弹性扩展与租户隔离。

怎么做配置

按Spine-Leaf规划Underlay路由与互联
配置VXLAN VTEP、VNI与租户隔离

按厂商手册核对思科/锐捷/华为/华三命令差异

运维 / 排障要点

多厂商命令同名不同义，上线前在实验环境核对语义与默认行为；排障统一看架构分层而非只套某一厂商命令。

原文：www.wsisp.com

Spine-Leaf VXLAN Fabric：EVPN-VXLAN三层解析

数通路由交换原理讲解高级其他

三层拆解EVPN-VXLAN Fabric

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

只把VXLAN理解为VLAN数量扩展，排障时无法区分Underlay、Overlay与控制面故障层级。

核心技术

将Fabric拆为三层：底层三层Underlay用尽所有链路转发，中层VXLAN封装租户流量，上层EVPN控制面通告可达性，分层定位故障。

怎么做配置

Underlay：逐链路启用路由协议并验证等价多路径
Overlay：配置VTEP、VNI与VXLAN封装
控制面：建立EVPN BGP邻居并开启MAC/IP通告
验证：分层检查路由、隧道与转发表

运维 / 排障要点

按Underlay可达、EVPN通告、VXLAN转发表逐层查，不要直接改Overlay；某一层异常时先修复该层再复测上层。

原文：choiceguidelab.com

Spine-Leaf与VXLAN EVPN数据中心Fabric指南

数通路由交换架构设计进阶其他

Spine-Leaf+EVPN告别STP阻塞链路

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

传统数据中心二层靠STP防环会阻塞链路，已付带宽无法使用且扩展与多归属能力受限。

核心技术

用Spine-Leaf全互联提供多条等价路径，Underlay跑三层路由，Overlay用VXLAN EVPN通告主机信息，替代STP阻塞实现全带宽转发。

怎么做配置

规划Spine-Leaf全互联与点到点互联链路
Underlay部署OSPF/EBGP并保证VTEP环回可达
Leaf上部署VXLAN VTEP与VNI映射
BGP EVPN地址族通告MAC/IP路由
接入侧用MLAG/LACP做双归属冗余

运维 / 排障要点

先保证Underlay的VTEP可达再查EVPN邻居与MAC/IP通告；STP残留阻塞或等价路径缺失会表现为Overlay不通。

新华三EVPN配置限制与VXLAN隧道创建

数通路由交换配置实战进阶新华三

EVPN启用前先切标准模式并重启

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

EVPN部署时若设备工作模式不符或隧道关联方式冲突，功能无法生效且配置后仍不通。

核心技术

先用system-working-mode standard切至标准模式、保存并重启使EVPN生效，再按EVPN自动或手工方式创建隧道且避免同VXLAN冲突关联。

怎么做配置

system-view
system-working-mode standard
保存当前配置文件
重启设备使工作模式生效
l2vpn enable并配置EVPN与VXLAN隧道
注意自动与手工隧道不能同关联同一VXLAN

运维 / 排障要点

切换工作模式前务必保存配置并安排重启窗口；重启后先确认模式已生效再下发EVPN，避免配置看似成功却不生效。

原文：www.h3c.com

新华三EVPN VXLAN与数据中心互联DCI配置

数通路由交换配置实战高级新华三

EVPN自动建VXLAN隧道实现DCI互联

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

多数据中心二层互联时，VXLAN隧道创建方式冲突或IPv6隧道限制易导致互联不通、业务无法扩展。

核心技术

VXLAN隧道可由EVPN自动创建也可手工创建，但隧道目的相同者不能关联同一VXLAN；IPv6场景须满足公网侧与IRF端口板卡及承载限制。

怎么做配置

system-view
l2vpn enable
创建VSI并关联VXLAN ID
配置EVPN实例、RD与VPN-Target
选择EVPN自动创建或手工创建VXLAN隧道
跨数据中心时按DCI场景关联隧道与VXLAN

运维 / 排障要点

用display查VXLAN隧道与VSI状态；常见坑是自动与手工隧道混关联同一VXLAN，以及IPv6隧道忽略SH系列接口板等限制。

原文：wwwsg.h3c.com

华为云Direct Connect专线路由故障排查

数通路由交换故障排查进阶华为

专线访问VPC不通先查路由与BGP

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

企业经专线访问华为云VPC不通时，难以判断是静态路由未下发、BGP邻居异常还是ER转发环节出错。

核心技术

分场景排查：先确认虚拟接口静态路由已下发或BGP对等已建立，再逐段核对VPC路由表与经企业路由器ER的路由传播。

怎么做配置

登录华为云专线控制台查看虚拟接口状态
核对VPC路由表中专线静态路由是否已下发
核对BGP对等体状态与通告路由
经企业路由器ER时核对ER路由表与传播
逐段复测云下到VPC的连通性

运维 / 排障要点

不要只看邻居Up，要核对实际收到的前缀与VPC/ER路由表是否一致；静态与BGP混用时注意路由优先级与漏下发。

原文：support.huaweicloud.com

新华三典型故障：VLAN终结资源不足处理

数通路由交换故障排查进阶新华三

VLAN终结资源不足的典型排障思路

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

配置VLAN终结时提示资源不足，导致终结子接口无法下发、相关业务无法按规划开通。

核心技术

按案例处理过程从报错现象回溯VLAN终结的资源占用与规格约束，清理或调整终结配置释放资源，再复测下发结果。

怎么做配置

记录报错时刻的VLAN终结配置与操作步骤
display vlan 查看已有VLAN与终结子接口
display interface 查看相关接口状态与计数
核对资源占用与产品规格限制
清理冗余终结配置或改用其他终结方式后复测

运维 / 排障要点

排障先保存报错原文与资源占用快照再做清理，避免误删在用终结配置；复测时同步看接口状态与业务流量是否恢复。

原文：dlaz.h3c.com

华为MPLS VPN：PE-CE间EBGP路由交换配置

数通路由交换配置实战进阶华为

PE-CE用EBGP实现VPN站点路由交换

展开拆解：问题 → 原理 → 配置 → 运维

解决什么问题

MPLS VPN客户站点接入时，PE与CE之间路由不交换会导致站点前缀无法进入骨干、跨站点互访中断。

核心技术

PE与CE建立EBGP邻居，PE在VPN实例地址族下与CE交换站点路由，再由骨干侧分发VPN路由，实现站点路由隔离接入与互通。

怎么做配置

system-view
bgp <as-number>
router-id <ipv4-address>（可选）
ipv4-family vpn-instance <vpn-instance-name>
peer <CE地址> as-number <CE-AS>

运维 / 排障要点

用display bgp peer查邻居是否Established、用VPNv4路由表查收发前缀；常见坑是AS号写反、未进VPN实例地址族或CE路由未引入。

原文：info.support.huawei.com
